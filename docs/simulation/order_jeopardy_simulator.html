How Flink Handles Unpartitioned MSK + 1,000 Events

Java 21 + RocksDB
1. Zero Producer Breaking Changes (AWS MSK)
Flink consumes unpartitioned flowable.activity.events and domain topics, drops ~95% non-mapped Flowable micro-events in memory, and executes keyBy(order_id) with a 10s out-of-orderness watermark.
2. Independent Lifecycle TTLs
ORD-2026-88412 (iPhone 18 Pro) closes in ~3 days and evicts from RocksDB. TRD-2026-55091 (Google 10 Pro Trade-In) stays active up to 60 days with its own ONNX survival-model timers, joined via PostgreSQL order_relationships.
3. Cross-Order Signals (No Distributed Locks)
When CHG-2026-10294 (Payment Update Change Order) starts, Flink publishes PAUSE_SLA_CLOCK to jeopardy.cross-order.signals keyed by ORD-2026-88412. On resolution, it emits RESUME_SLA_CLOCK.
